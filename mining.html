Why mine Numen

Work that means something

Permissionless by design

No stake, no signup, no allowlist. Point a node at the testnet chain spec and start scanning for seals.

Your keys stay offline

Mining never needs a private key. The payout AccountId is embedded in block headers — generate a keypair offline and pass only the SS58 address.

Scheduled emission

Blocks currently mint 16 NMN, halving every 12.5 million blocks (~4 years). Total mined issuance is capped at 400M NMN.

Ordinary hardware

The work is mesh growth plus ray sampling — built for CPUs. Four cores and 4 GB of RAM make a comfortable miner.

Self-healing difficulty

ASERT relaxes difficulty if hashpower drops and re-tightens as it returns, without multi-day stall periods.

Verifiable everything

Every seal can be re-executed deterministically by any node. There is nothing to trust — only parameters to check.

Setup guide

From zero to first seal

Six steps from a clean machine to earning rewards.

Download the binary

Grab a release for Linux x86_64 or macOS arm64. Each archive contains the numen binary and testnet-raw.json.

Sync a node

Start the client against the testnet chain spec and let it catch up.

Create a payout address offline

Generate an SS58 address on an air-gapped machine (e.g. subkey generate). The node refuses invalid addresses — by design.

Enable the miner

Pass your payout address via --miner. Optionally cap threads with --node-miner <n>.

Scan for seals

The in-process scanner grows seeded meshes and sweeps surfaces until a work hash meets target.

Collect rewards

Valid seals author blocks. The reward accrues directly to your payout account.

The commands

$ tar -xzf numen-linux-x86_64.tar.gz && cd numen-linux-x86_64
$ ./numen --chain testnet-raw.json
$ ./numen --chain testnet-raw.json --miner <YOUR_ADDRESS> --node-miner <THREADS>

External miners

Drive the node over RPC

Drop --node-miner to leave authoring entirely to external rigs. They pull tasks, scan independently, and return seals over standard JSON-RPC.

RPC method

mining_getTask

Fetch the current task: header hash, difficulty target and seed derivation inputs for this round.

RPC method

mining_subscribeTask

Subscribe and receive a fresh task push roughly every second — no polling needed.

RPC method

mining_submitSeal

Submit a valid seal. The node verifies it locally before propagating the block.

Example · fetch current task
curl -X POST http://127.0.0.1:9944 \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "mining_getTask",
    "params": [],
    "id": 1
  }'

How the loop fits together

  1. Rig subscribes to tasks on its own full node.
  2. Each task seeds a fresh asteroid mesh + target.
  3. Rig scans until hash(features) ≤ target.
  4. Seal goes back via RPC; node validates and authors.
  5. New round begins against the next header.

A browser-sized approximation of this exact loop runs on the homepage simulator.

Security notes

Keys never touch miners

Generate the payout keypair offline (subkey generate) and configure only the public SS58 address on the mining node. Compromise of a rig costs you hardware time, not funds.

Mining RPC stays local

Mining endpoints are served on your node’s local interface. Never expose them publicly — point external rigs at your own endpoint only.

Ready when you are.

A modest machine, a payout address, and one command line away from participating in consensus.
